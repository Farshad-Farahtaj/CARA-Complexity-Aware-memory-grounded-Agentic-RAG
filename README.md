# 🏥 CARA — Complexity-Aware, memory-grounded Agentic RAG

A Retrieval-Augmented Generation (RAG) chatbot that answers medical questions grounded in a corpus of medical textbooks, with a built-in evaluation pipeline comparing multiple LLMs on the MedQA benchmark.

---

## ✨ Features

- 💬 ChatGPT-style dark web UI — no React, no Vue, pure HTML/CSS/JS
- 🔍 Semantic search over 18 medical textbooks (MedQA corpus) using local vector embeddings
- 🤖 Answers grounded in retrieved textbook passages, generated by any of four supported LLMs
- 📊 Evaluation script benchmarking model accuracy on a fixed MedQA test sample, with per-model resume support
- 💾 Automatic per-session chat backup to `chatBackup/` as JSON
- ⚡ FastAPI backend with instant startup — index loaded once at boot

---

## 🧠 How It Works

### Offline — Indexing (run once)

```
docs/ (medical textbooks, .txt)
       │
       ▼
[ingest.py]
  → split into 512-token chunks
  → embed locally with nomic-embed-text (via Ollama)
  → store vectors in ./chroma_db
```

### Online — Query (every request)

```
User question
      │
      ▼
[Embed question] → vector (nomic-embed-text)
      │
      ▼
[ChromaDB] → top 3 semantically similar chunks
      │
      ▼
[LLM] ← chunks + question as context
      │
      ▼
  🤖 Grounded answer
```

## ⚙️ Setup

### 1. Clone the Repository

```bash
git clone https://github.com/Farshad-Farahtaj/CARA.git
cd CARA
```

### 2. Install Dependencies

```bash
pip install -r requirements.txt
```

### 3. Install Ollama and Pull the Local Models

Download Ollama from [ollama.com/download](https://ollama.com/download), then:

```bash
ollama pull nomic-embed-text
ollama pull medgemma1.5:4b
```

### 4. Configure Your API Keys

Create a `.env` file in the project root:

```env
GEMINI_API_KEY=your_google_ai_studio_key_here
GROQ_API_KEY=your_groq_key_here
```

> Both are free tiers, no credit card required. Get a Gemini key at [aistudio.google.com](https://aistudio.google.com) and a Groq key at [console.groq.com](https://console.groq.com).

## 🚀 Usage

### Step 1 — Ingest Documents

Run **once** to build the vector database from your documents:

```bash
python backend/ingest.py
```

### Step 2 — Start the Web App

```bash
uvicorn backend.api:app --reload
```

Open your browser at **[http://localhost:8000](http://localhost:8000)**.

### Optional — Terminal Interface

```bash
python backend/query.py
```

### Optional — Evaluate Model Accuracy

Each model is run and saved separately, so a rate limit or outage on one provider never affects the others. Progress is saved after every question, so an interrupted run resumes where it left off.

```bash
python backend/evaluate.py gemma4      # or: medgemma, gptoss, qwen38
python backend/evaluate.py summary     # combined results table so far
```

## 🛠️ Tech Stack

| Layer | Technology |
|---|---|
| RAG Framework | [LlamaIndex](https://www.llamaindex.ai/) |
| Vector Database | [ChromaDB](https://www.trychroma.com/) — local, no cloud needed |
| Embedding Model | `nomic-embed-text` (local, via Ollama) |
| LLMs | Gemma 4 31B, MedGemma 4B, GPT-OSS-120B, Qwen3.8 27B |
| Backend | [FastAPI](https://fastapi.tiangolo.com/) + Uvicorn |
| Frontend | Vanilla HTML / CSS / JavaScript (no frameworks) |
| Environment | Python 3.10+ |

## 📄 Dataset

Document corpus and evaluation questions are drawn from **MedQA** (Jin et al., 2020), specifically the US 4-option subset and its accompanying 18-textbook corpus.
